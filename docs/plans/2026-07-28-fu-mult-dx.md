# fu_mult_dx — Implementation Plan

**Spec:** `docs/specs/2026-07-28-fu-mult-dx-design.md`

**Revised:** DesignWare `DW_mult_dx` was built, verified, and synthesized first; it cost ~2× area and
was slower (full 128-bit product, no low-only mode). Scrapped in favor of a **hand-written 64/32
multiply-low** datapath. The testbench (`tb/tb_fu_mult_dx.sv`) is implementation-agnostic and unchanged.

## Steps

1. **Spec** (revised — hand-written multiply-low).
2. **RTL** — replace the DW instantiation with four 32×32 block products (`P00` full, `P01/P10/P11`
   low-32) and a mode-routed high word. Same interface/handshake. Verify `PASS:` on the existing tb.
3. **README** — redefine the `_dx` family (dual 64/32; DW where it wins, hand-written otherwise);
   rewrite the `fu_mult_dx` section.
4. **Commit series** (WillWheatley27, subject-only, no AI traces): docs → RTL replace → README; push.
5. **Synthesize** SAED14nm both corners (after the DW re-synth on the same TOP finishes). Record clean
   corners; compare to hand-written `fu_mult_decomp` (64/32/16) and the scrapped DW numbers.
6. **Chart** — append `mult_dx` (hand-written) as a new bottom row of the 64/32 (`_dx`) family chart.

## Checks

- Hand-written datapath verified against the existing golden (lint `-Wall` clean, 20k random PASS).
- Datapath builds only the low PP array; expected area well below the DW full-product block and near
  `fu_mult_decomp`.
